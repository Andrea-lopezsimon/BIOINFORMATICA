Preparación

Necesitamos tener instalado el paquete ncbi-blast+, que en Linux y en WSL2 se puede instalar mediante sudo apt install ncbi-blast+. Este método no instalará la versión más reciente, pero será suficiente. También podemos seguir las instrucciones de instalación en este enlace.

Los ejecutables de BLAST son programas independientes de R, y deben ejecutarse en un entorno de Bash, no en la consola de R. La ayuda completa de cada programa también puede consultarse en un terminal de Bash, por ejemplo con la orden blastn -help.

En el ejercicio 3 necesitaremos también los programas datasets y dataformat, que podéis descargar desde este enlace. Es recomendable guardar los ejecutables en una carpeta del PATH, como /usr/local/bin/. Además, usaremos el paquete de R Biostrings, que en caso de no tener instalado, podéis instalar con BiocManager (no con install.packages()!):

BiocManager::install('Biostrings')

Objetivos

BLAST ejecuta alineamientos locales entre una secuencia “problema” o query, generalmente no muy larga, y un conjunto grande de secuencias (la base de datos) entre las que esperamos encontrar alguna secuencia homóloga a la query. Cada secuencia de la base de datos que pueda alinearse con la query se la llama subject en el alineamiento. Los objetivos de esta práctica son:

  1. Identificar proteínas ortólogas entre dos especies con BLASTP.

  2. Realizar un PSI-BLAST contra la base de datos Swissprot.

  3. Determinar el origen de las lecturas que no pudieron ser mapeadas a su genoma de referencia, usando BLASTN remoto.

Ejercicio 1

Una estrategia habitual para identificar genes ortólogos es comprobar si cada uno es, respecto del otro, su mejor resultado de BLAST. Lo que en inglés llaman reciprocal best hits. Aunque se trata de un método heurístico, los resultados son bastante fiables. Vamos a practicarlo entre dos proteomas que debes haber descargado, y que primero debemos enmascarar e indexar para BLAST.

Encontrar genes ortologos que descienden de un ancestro común, cada especie hereda genes de un ancestro común, pero a veces hacen por duplicado, y esas copias entre ellas sin parálogas. Para estudiar la filogenia de las especies se usan proteínas ortólogas de cada especie. Esto es para identificar ortólogos.

Al buscar las proteínas de una especie en el proteoma de la otra pueden haber más de un hit. En las tablas de buc2blo y blo2buc se compara cada proteina de una especie con la de mejor coincidencia de la otra. Al hacer match se comparan las dos para ver si la coincidencia es la misma y se puede considerar que esas dos proteínas sean ortólogas.

Estos serían los comandos ha seguir desde el R:

if [ ! -e ../../data/2026-03-24/buchnera.paa ]; then
   # Creamos un archivo para enmascarar zonas de baja complejidad:
   if [ ! -e buchnera_seg.asnb ]; then
      segmasker -in ../../data/2026-03-24/buchnera.fa \
                -infmt fasta \
                -parse_seqids \
                -outfmt maskinfo_asn1_bin \
                -out ../../data/2026-03-24/buchnera_seg.asnb
   fi
   # Y indexamos el archivo FASTA para BLAST:
   makeblastdb  -in ../../data/2026-03-24/buchnera.fa \
                -input_type fasta \
                -dbtype prot \
                -parse_seqids \
                -mask_data ../../data/2026-03-24/buchnera_seg.asnb \
                -out ../../data/2026-03-24/buchnera \
                -title "Proteoma de Buchnera"
fi
# Hay que repetir todo esto para Blochmannia.
if [ ! -e ../../data/2026-03-24/blochmannia.paa ]; then

Realizar las búsquedas de BLASTP

El objetivo es encontrar la proteína de Blochmannia ocreatus que más se parece a cada una de las proteínas de Buchnera aphidicola, y viceversa. Entonces, seleccionaremos las parejas de proteínas que sean recíprocamente las más similares una de otra, por ser más probablemente ortólogas. Otras relaciones de semejanza no recíprocas pueden ser debidas a la paralogía.

De Buchnera aphidicola hacia Blochmannia ocreatus

       -out buc2blo.txt \

       -evalue 0.001 \

De esta manera obtenemos para el proteoma de cada especie una tabla en la que se relaciona cada proteína con la más similar de la otra especie. Algunas proteínas pueden tener más hit en la otra especie, así que tenemos que buscar las que tienen mayor coincidencia mutuamente, que serán las ortólogas.

Nota

Revisa los argumentos utilizados, prueba otros si quieres y asegúrate de que son adecuados. Puedes consultar la ayuda con blastp -help en el terminal.

-query identifica el archivo de entrada

-db indica la base de datos con la que se compara el archivo de entrada

-out da nombre al archivo de salida

-outfmt indica el formato que tendrá la tabla de salida y que información contiene cada salida

-evalue designa un valor límite a partir del cual se guardan las coincidencias (0.001 en este caso).

-max_target_seqs define el número máximo de secuencias alineadas que queremos guardar (1 en este caso)

Comparación de resultados

Vamos a crear una tabla en R a partir de los archivos que acabamos de obtener con las comparaciones de los proteomas. En estas tablas se compara cada proteína de una especie con la mejor coincidencia de la otra proteína

buc2blo <- read.table(
   'buc2blo.txt',
   col.names = c('query', 'subject', 'qlen', 'slen',
                 'length', 'evalue', 'bitscore')
)
blo2buc <- read.table(
   'blo2buc.txt',
   col.names = c('query', 'subject', 'qlen', 'slen',
                 'length', 'evalue', 'bitscore')
)

NOTA

Echa un vistazo a estas tablas de resultados. ¿Sabrías identificar las parejas de proteínas que son recíprocamente la que más se parece una a la otra?

Una posible solución: Añadimos a buc2blo una nueva columna llamada reverse con el nombre de la mejor coincidencia de la tbla blo2buc con la función match. Asi comparamos si la mejor coincidencia de Buchnera a Blochmannia es la misma que de Blochmannia a Buchnera. Y después comparamos si la mejor coincidencia de Buchnera a Blochmannia es la misma que de Blochmannia a Buchnera. De esta manera, una vez tenemos todas las coincidencias las extraemos a una nueva tabla, que contiene las posibles proteínas ortólogas.

buc2blo$reverse <- blo2buc[
   match(buc2blo$subject, blo2buc$query),
   'subject'
]
coincidencias <- buc2blo[
   buc2blo$query == buc2blo$reverse,
   c('query', 'subject')
]

NOTA

Consulta la ayuda de psiblast y asegúrate de entender para qué sirven los argumentos que hemos usado. Por ejemplo, ¿cuál es la diferencia entre -evalue y -inclusion_ethresh?¿Cómo harías que la búsqueda fuera más sensible todavía?

->-evalue controla el umbral de significancia para filtrar qué alineamientos se muestran en el reporte final. El valor que hemos usado es de 0,1, que es el más estricto. Es decir, lo que hace es controlar lo que ves en la pantalla o archivo de salida. Es un filtro de lectura

->Inclusion_ethresh controla las secuencias que se usan para construir la matriz. Define la evolución del perfil entre iteraciones. El valor que hemos usado, 7, es muy poco estricto.

Para que la búsqueda sea más sensible y encontrar parientes muy lejanos podmeos utilizar tres maneras:

-num_interations: para aumentar el número de interacciones

-inclusion_ethresh: para relajar, permites que entren más secuencias, aunque sean más dudosas, lo que puede hacer que el perfil sea muy genérico.

-matrix: para cambiar la matriz de sustitución y buscar parientes más lejanos (en este caso utilizamos la matriz BLOSUM62).

Ejercicio 3. Origen de la contaminación en un archivo FASTQ

El archivo ../../data/contaminacion.fa.gz contiene 33174 lecturas procedentes de un experimento de secuenciación del insecto Aphis aurantii, con Ion Torrent. (SRR13258790). Concretamente son las lecturas que no han podido mapearse al genoma de referencia (GCA_055615905) de este insecto. Hay dos motivos principales por los que muchos fragmentos no pueden mapearse al genoma de referencia: o bien el genoma de referencia es incompleto, o bien los fragmentos no pertenecen a esa especie. La secuenciación no distingue al individuo de interés de sus simbiontes, parásitos o presas. Los fragmentos de ADN secuenciados que no proceden del individuo diana se consideran contaminación. El objetivo de este ejercicio es determinar la procedencia de estos fragmentos mediante BLASTN remoto a la base de datos nr (no redundante). Lo que nos interesa es sólo el origen taxonómico de la secuencia más parecida a cada una de esas lecturas.

Identificación taxonómica

La única información taxonómica que podemos obtener de las secuencias encontradas cuando realizamos un BLAST remoto es el identificador taxonómico. Esta restricción tiene por objetivo agilizar el servicio remoto. Ahora es asunto nuestro saber a qué especies corresponden los identificadores, de manera automática. Hay varias opciones. Para no tener que descargar la base de datos taxonómica, intentaremos recuperar la información completa con una nueva consulta remota. Esta vez, con los programas  datasets  y  dataformat  de NCBI, que ya conocéis.

# Extraemos los identificadores taxonómicos (columna 9) de "resultado.txt":
